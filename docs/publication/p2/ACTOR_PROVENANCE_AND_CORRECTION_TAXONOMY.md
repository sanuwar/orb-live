# Actor Provenance and Correction Taxonomy

**Purpose:** define a schema for classifying who/what performed each research activity and what kind of defect each correction addressed, so that a future manuscript never states an attribution the committed record cannot support. This document defines the schema and applies it to the M43–M55 correction record already summarized in P1's `HUMAN_LLM_WORKFLOW_AUDIT.md`; it does not reclassify any figure, and where the underlying commit history does not distinguish actors precisely, the entry is marked `UNKNOWN` rather than guessed.

## Actor categories

| Category | Definition |
|---|---|
| `HUMAN_OPERATOR` | The repository owner/operator, acting directly (defining scope, approving protocols, authorizing runs, merging PRs). |
| `CLAUDE_CODE` | Claude Code/Claude, acting under a human work order. **The exact model and version require verification from retained records before appearing in any manuscript** — this taxonomy does not treat any specific model name (e.g., a particular Claude version) as established fact merely because a document elsewhere in this repository names one; see `AI_USE_DISCLOSURE_DRAFT.md`'s own verification checklist. |
| `CHATGPT_CODEX` | ChatGPT/Codex, used for the P1 audit and draft materials per `AI_USE_DISCLOSURE_DRAFT.md` (exact scope of use not committed beyond that statement). |
| `AUTOMATED_TEST` | A committed pytest/regression test executing deterministically, with no human or AI judgment involved in that specific execution. |
| `CI` | GitHub Actions or an equivalent automated pipeline, executing committed test/check commands. |
| `MIXED_HUMAN_AI` | An activity the commit record shows as jointly performed (e.g., an AI-drafted diagnosis a human then verified against a specific artifact before accepting it) where neither party alone is a complete or accurate attribution. |
| `UNKNOWN` | The committed record does not distinguish which actor(s) performed this specific activity. **This category exists precisely so P2 never fabricates a more specific attribution than the evidence supports; using it is not a gap in this taxonomy, it is this taxonomy working correctly.** |

## Activity categories (applied per research or correction event)

`PROPOSAL`, `PROTOCOL_DRAFTING`, `IMPLEMENTATION`, `EXECUTION`, `DEFECT_INTRODUCTION`, `DEFECT_DETECTION`, `DIAGNOSIS`, `CORRECTION`, `RERUN`, `VERIFICATION`, `INTERPRETATION`, `APPROVAL`, `MERGE_ACCOUNTABILITY`.

## Defect categories

`DATA_PROVENANCE`, `UNIVERSE_CONSTRUCTION`, `TIMING_LOOKAHEAD`, `ENTRY_EXIT_LOGIC`, `CAPITAL_ACCOUNTING`, `COST_MODELING`, `AGGREGATION`, `STALE_ARTIFACT`, `NARRATIVE_ARTIFACT_INCONSISTENCY`, `CONFIGURATION_SAFETY`, `CITATION_PROVENANCE_AMBIGUITY`.

## Note on the M55 row (corrected)

An earlier draft of this document attributed M55's `DEFECT_INTRODUCTION` and `CORRECTION` actor cells to `CLAUDE_CODE`, reasoning "per this session's own commit history... session continuity." That attribution is withdrawn here. The P2 evidence boundary is **committed evidence** — `docs/research/*.md`, hash manifests, Git commit/author metadata, and code/tests actually in the repository — not the current interactive session's own memory of what it did. No committed artifact in the M55 record (commit messages, the checkpoint ledger, or the milestone report) states an exact, verifiable model/tool identity for who authored the specific lines that introduced or fixed the two M55 initialization defects. "This session recalls doing it" is not committed evidence by that standard, and an unverified exact Claude model identifier must not be treated as established evidence for an attribution that will appear in a manuscript. The M55 row's `DEFECT_INTRODUCTION` and `CORRECTION` cells are therefore `UNKNOWN`, on the same basis as every other milestone's `DEFECT_INTRODUCTION`/`CORRECTION` cells in this table. This does **not** extend to M55's `DEFECT_DETECTION` cell, which remains `AUTOMATED_TEST` — that attribution rests on a committed, executable gate having actually failed and reported the defects, which is independent of any uncertainty about who wrote the code the gate checked.

## What this taxonomy demonstrates, honestly

Every `CORRECTION` actor cell in this table is `UNKNOWN`, and every `DEFECT_INTRODUCTION` actor cell is `UNKNOWN`, across all seven milestones including M55 after this correction. `DEFECT_DETECTION` is mixed, and stating it as uniformly `UNKNOWN` would itself be inaccurate: six of seven (`M45`, `M46`, `M47`, `M48`, `M50`, `M52`) are `UNKNOWN`, because P1's own record describes an "independent review" or "manual cross-check" without naming an actor. **M55's `DEFECT_DETECTION` is `AUTOMATED_TEST`, not `UNKNOWN`** — a committed, executable initialization gate (`scripts/monitor_momentum_prospective.py`'s ten-item gate) is what actually failed and reported the two defects, which is a genuinely different evidentiary situation from an informal review, and this taxonomy preserves that distinction rather than flattening it. This mixed picture is not a defect in this document — it is the correct, evidence-grounded output of applying the taxonomy to a record that (as P1's `HUMAN_LLM_WORKFLOW_AUDIT.md` already stated) does not consistently actor-label "independent review," and to a P2 evidence boundary that excludes uncommitted session recall and context-based inference (see the M50 `VERIFICATION` correction above). A future manuscript must not upgrade any `UNKNOWN` cell to `HUMAN_OPERATOR`, `CLAUDE_CODE`, or `MIXED_HUMAN_AI` without new evidence (e.g., retained prompt/session logs reviewed and cited by a human before submission, per `AI_USE_DISCLOSURE_DRAFT.md`'s own verification checklist) — and any such future evidence must itself name a verified exact tool/model identifier, not an assumed one. Conversely, a cell that is already `AUTOMATED_TEST` on committed, executable evidence (M55's detection) must not be weakened to `UNKNOWN` for the sake of a uniform-looking table.

## Rules for future milestones

To avoid perpetuating this gap, any milestone from P3 onward should record, at minimum, the `EXECUTION` and `VERIFICATION` actor for each defect found, at the time it is found — not reconstructed retroactively. This is a process recommendation for future work, not a retroactive correction of M43–M55 (see the P1 correction boundary: P2 does not rewrite P1 or earlier milestones).
