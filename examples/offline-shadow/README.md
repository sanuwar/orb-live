# Offline shadow fixture examples

These examples document the fixed fixture catalog. They contain no provider
payloads, account data, paths, credentials, network destinations, or signing
material. Construct manifests through `build_fixture` so IDs and timestamps
remain bound by the typed package contract.

Available scenarios:

- `SAFE_OFFLINE_COMPLETION`
- `OPERATOR_REVIEW_REQUIRED`
- `ACTIVE_SUSPENSION`
- `AMBIGUOUS_RESTART`
- `MISSED_HEARTBEAT`
- `ALERT_DELIVERY_UNCONFIRMED`
- `ACKNOWLEDGED_BUT_STILL_SUSPENDED`
- `READINESS_BLOCKED`
- `STALE_EVIDENCE`
- `DURABLE_RESTART`
